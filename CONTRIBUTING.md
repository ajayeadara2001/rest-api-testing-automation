# Contributing

Thank you for improving this portfolio project.

1. Do not add credentials, authentication tokens, or unredacted personal data.
2. Keep public API testing and local database testing clearly separated.
3. For each new test, include a stable ID, scenario, expected result, and evidence or result status.
4. Do not call a result “passed” unless execution evidence is available.
5. Update the relevant test matrix and execution report with any change.

Before opening a pull request, import the Postman collection, run the SQL scripts against a disposable local database, and verify the documentation links still work.
